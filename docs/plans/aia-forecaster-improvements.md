# Taking the Superforecasting Agent to AIA-Forecaster level

A formal improvement plan derived from a deep analysis of *AIA Forecaster: Technical Report* (Bridgewater AIA Labs, arXiv:2511.07678) mapped against our system. Source paper: ~/Downloads/2511.07678v1.pdf.

## Executive summary

Our fork already owns the AIA spine: parallel independent model quorum (forecasting/quorum.py run_quorum, ThreadPoolExecutor at :554) -> trimmed-geomean-of-odds pool (panel.aggregate_panel_estimates, panel.py:153-198 via bayes_toolkit.log_odds_pool) -> a judge that surfaces consensus/contradictions/blind_spots (quorum.py:262-333), plus a strong anti-market-echo soul (protocol.py:93-113) and rigorous data-driven signed-calibration-error machinery (calibration_bias.py). We are structurally AHEAD of the two failure modes the paper warns about (naive-LLM-aggregation and best-of-k selection): the committed number is a deterministic pool, never an LLM free-picking a value. But we are MISSING the four sharpest mechanical levers the paper proves, and every one is latent-but-unwired in our code: (1) an always-on TERMINAL Platt/scaled-log-odds calibration on p_final — we own the exact operator (bayes_toolkit.extremize == inv_logit(factor*logit(p)) == Baron Eq.2 == Platt no-shift) but every default factor is 1.0 (no-op) and panel.aggregate_panel_estimates returns the BARE pool (the paper's uncorrected 0.1140 regime); (2) a SUPERVISOR that resolves disagreement with FRESH targeted search and a confidence-gated override — our judge re-reasons over static traces, issues no queries, has no directional_confidence field, and its number is recorded but never overrides the pool; (3) a CONTENT-aware foreknowledge judge over cited text plus the two conservative robustness bounds (drop-flagged, worst-case-0.5) — our leakage check (ledger.py:11033) is a pure date heuristic with a binary kill-switch; (4) a SIMPLEX-constrained Brier regression to read off LLM-vs-market complementarity weights — entirely absent. Plus the inference-grade glue: a paired recenter-at-zero bootstrap + p-value (today _paired_brier_summary at ledger.py:11725 uses a parametric normal CI, no p-value), an ensemble-size bump to M~=10 with a benchmarked simple-mean baseline, and a foreknowledge-proof live MarketNightly harness. This plan dedupes the four theme docs into one ranked roadmap; the convexity/Jensen, geo-mean-of-odds, Platt==extremization-of-geometric-mean, and baseline-anchored-extremization results from the web context are folded in as formal upgrades, not just features. Net effect, mirroring the paper: terminal Platt is the single highest-leverage change (0.1140 -> 0.1076, ~5.6% Brier on an already-pooled aggregate), the agentic supervisor is next (0.1199 -> 0.1125), and the leakage judge + live benchmark + bootstrap convert our headline Brier into an HONEST, significance-backed, leak-proof superiority claim rather than a point estimate.

## Where we already lead

- Deterministic pool is the committed number, NOT an LLM picking a value: panel.aggregate_panel_estimates (panel.py:195-198) pools via trimmed-geomean-of-odds and the judge sits ON TOP, so we already avoid BOTH failure modes the paper documents (naive 'LLM reads all forecasts and re-emits a number' < mean, and best-of-k selection < mean). protocol.py:149 even forbids the agent from reinventing the aggregation.
- We own the exact extremization/Platt operator already: bayes_toolkit.extremize(p,factor)=inv_logit(factor*logit(p)) (bayes_toolkit.py:305-315) IS Baron 2014 Eq.2 and IS Platt no-shift; combine_forecasts already computes geometric-mean-of-odds then extremizes — literally Platt-of-the-geometric-mean, the paper's headline 'previously-undocumented equivalence'. We have the math; we just default factor=1.0 everywhere.
- Outlier-robust pooling is already the default: trimmed-geomean-odds with trim=1 (panel.py:163-166) is exactly the outlier defense, and median is a selectable aggregator (panel.py:120-121). We pool in log-odds space (the literature-recommended geometric-mean-of-odds), not arithmetic probability space.
- A genuinely rigorous downstream calibration measurement stack already exists: signed_calibration_error with CI + BH-FDR + empirical-Bayes shrinkage + per-bin reliability shape (_curve_shape) + ECE (calibration_bias.py), beyond the paper's held-out 2-param fit; we measure the bias direction per scope, we just don't yet feed it back into the committed number by default.
- An anti-market-echo, information-frontier, status-quo/path-driven SOUL is fully internalized (protocol.py:93-113, default_soul): market-mirroring is a SCORED failure, as-of-cutoff reasoning is enforced in prose, and refresh is steered toward the agentic path. The paper's market-masking insight is already our doctrine.
- Paired question-level comparison already exists (_paired_brier_summary, ledger.py:11725): per-question Brier deltas, agent/baseline wins/ties, and a 95% CI on the shared question set — the correct pairing structure; we only need to swap the parametric CI for a bootstrap + p-value.
- Time-aware backtest scaffolding is in place: per-case simulated_forecast_time + resolution_time + evidence_cutoff (ledger.py:10885-10919), frozen public Manifold/Kalshi 120-binary corpora with stored market and naive_0_5 baselines (benchmarks.py), and a leakage gate that already excludes failing cases from calibration — the chassis for a leak-proof eval is built.

## Top gaps vs the paper

1. No always-on terminal calibration: panel.aggregate_panel_estimates (panel.py:196) returns the BARE pooled probability with zero extremization, and every extremize default (combine_forecasts, thesis._EXTREMIZE_FACTOR, --extremize) is 1.0 (no-op). The committed p_final is the paper's uncorrected 0.1140 regime. The fixed alpha=sqrt(3) (Neyman-Roughgarden) convention is absent; the only sigmoidal correction (learning.py logit_scale) is lesson-gated, ESS>=60-gated, and capped at alpha in [0.8,1.2] — so it almost never fires and never extremizes meaningfully.
2. The supervisor/judge does NOT search to resolve disagreement: build_judge_prompt (quorum.py:275-333) hands the judge only the static panel block; it re-reasons but issues no base-rate/fact-check queries — the paper's load-bearing step 2. This is the documented difference between 'matches mean' and 'beats mean'.
3. No confidence-gated override: JudgeSynthesis (quorum.py:127-152) has no directional_confidence field, and the judge's probability is recorded (quorum_jobs.py:210) but the committed aggregate stays the pool — we get neither the upside of a high-confidence override nor the downside protection of falling back to the pool on low confidence.
4. Leakage check is a pure DATE heuristic with a binary kill-switch: leakage_check_status='passed' iff ambiguous==0 (ledger.py:11033) — no LLM-as-judge reads the cited TEXT for post-cutoff knowledge, and the two conservative robustness bounds (drop-all-flagged; assign-0.50/Brier-0.25 to heavily-flagged) are absent. Our headline Brier is not yet defensibly leak-proof. load_wikipedia_pages also serves the LIVE page (source_adapters.py), the exact Sub-type-B time-travel failure.
5. No foreknowledge-proof LIVE benchmark: we score resolved/backtest cases and import live prices as evidence, but there is no MarketNightly job that snapshots still-OPEN liquid markets, strips price, blacklists prediction-market domains, and scores quick-resolvers vs truth / open ones vs de-vigged price. The only structurally-unleakable test does not exist.
6. No simplex-constrained market+LLM ensemble: market price enters only as a static advisory weight (market_quality.py:39); there is no convex (w>=0, sum=1) Brier-minimizing regression of outcome on {market_price, llm_forecast} with bootstrap CIs and leave-one-out ensemble Brier, so we cannot read off 'does the market add signal beyond us, and at what weight'. The paper shows the ensemble beats BOTH inputs (0.106 vs 0.111/0.126).
7. Significance is parametric, not bootstrapped: _paired_brier_summary (ledger.py:11748-11755) uses a normal-approx CI (1.96*sqrt(var/n)) and emits NO p-value and NO Win-Rate-vs-Best across all baselines, so our 'edge' is a point estimate, not a 'statistically indistinguishable from / better than experts' verdict — and there is no human/superforecaster baseline at all.
8. Ensemble size is small and role-based, not stochasticity-first: self preset samples=3 (quorum.py:81), panel runs 5 fixed ROLE framings — neither adopts ~10 independent same-brief draws, and nothing benchmarks the convexity-backed simple mean (bayes_toolkit.mean_probability exists at :265 but is not a selectable panel aggregator) or plots the Brier-vs-ensemble-size curve to justify M from data.
9. No per-agent adaptive search trace: the agent CAN search iteratively but we do not record the E1->E2->...->En chain as an auditable artifact, do not enforce 'multi-step search on no-watched-source questions', and the deterministic refresh_forecast (fixed-query re-pool) remains the live re-commit default — the non-agentic style the paper shows underperforms.

## Roadmap
### P0 — highest accuracy-per-effort, do first

#### P0.1 — Terminal fixed-alpha Platt calibration on every committed aggregate (alpha=sqrt(3), no-shift)  *(effort: S)*

- **Method:** Always-on final-stage Platt/scaled-log-odds correction f_alpha(p)=inv_logit(alpha*logit(p)) applied once to the single reconciled p_final, alpha=sqrt(3)~=1.73 fixed a priori (Neyman-Roughgarden, the n>50 limit of the closed-form d). This is the paper's production move (Platt scaling) and is mathematically identical to extremizing the geometric mean of odds — the operator we already own.
- **Implementation:** 1) Add platt_scale(p, alpha=math.sqrt(3.0), d=1.0)=inv_logit(alpha*logit(p)+math.log(d)) to forecasting/bayes_toolkit.py next to extremize; make extremize(p,factor) a thin alias of platt_scale(p,alpha=factor) so there is ONE recalibrator. 2) Refactor learning.py:104-106 to call platt_scale and DELETE the private _logit/_sigmoid copies (learning.py:230-236) — kill the duplicate operator. 3) In panel.aggregate_panel_estimates (panel.py:196), after the pool, apply platt_scale with alpha from resolve_question_config (the config plumbing from tasks #161/#162 already exists); default config alpha_extremize=1.0 (no-op) so existing behavior is byte-identical, set the DESK default to sqrt(3) behind the existing forecastSettingsModal (#164). Compose MULTIPLICATIVELY with the existing learned logit_scale (learning.py:105) so the fixed de-hedge and the measured per-scope correction stack. 4) Persist pre_extremize_probability + applied alpha (PoolResult already carries pre_extremize_probability, bayes_toolkit.py:335; learning.py:109 already records raw_probability). 5) Add a hooks/builtins.py WARN when a committed LIVE snapshot skipped the calibration stage (mirror _check_lessons_applied at builtins.py:208); keep exploratory origin exempt.
- **Files:** forecasting/bayes_toolkit.py (platt_scale + extremize alias), forecasting/learning.py:104-110,230-236, forecasting/panel.py:196, forecasting/question_spec.py (alpha_extremize key), forecasting/calibration_bias.py (compose with logit_scale), forecasting/hooks/builtins.py (calibration-applied WARN)
- **Expected gain:** Paper: Brier 0.1140 (no correction) -> 0.1076 (fixed-param Platt), ~5.6% relative, concentrated in the 0.2-0.4/0.6-0.8 mid-confidence bins. Our committed aggregate is CURRENTLY the uncorrected regime, so this is the single highest-leverage change and counters RLHF hedging-toward-0.5 on EVERY commit, not just opt-in ones.

#### P0.2 — Paired recenter-at-zero bootstrap + two-sided p-value + Win-Rate-vs-Best  *(effort: S)*

- **Method:** Question-level paired bootstrap: recenter per-question Brier deltas at zero, draw ~10k resampled means, read off a two-sided p-value, and add a Win-Rate-vs-Best statistic across ALL baselines — turning the point-estimate edge into a 'statistically indistinguishable-from / better-than' verdict (the paper's framing for matching superforecaster median).
- **Implementation:** Replace the parametric CI in _paired_brier_summary (ledger.py:11748-11755) with a deterministic bootstrap: deltas[i]=baseline_brier_i - agent_brier_i; d0=deltas-mean(deltas); draw B=10000 means of d0 via a seeded random.Random; p=fraction(|boot_mean|>=|mean(deltas)|); percentile CI from the UNcentered resamples. Add a sibling _win_rate_vs_best over the full baseline set (fraction of questions where agent Brier <= every baseline). Surface paired_p_value + win_rate_vs_best in backtesting.best_summary (backtesting.py:78) and build_forecasting_evidence_status (backtesting.py:109). Keep the existing wins/ties counts. Add a p=0.5 floor (Brier 0.25) as a reported sanity anchor next to mean Brier.
- **Files:** forecasting/ledger.py:11725-11760 (_paired_brier_summary bootstrap + _win_rate_vs_best), forecasting/backtesting.py:78,109
- **Expected gain:** Diagnostic/honesty: converts our raw-edge readiness claim into a significance-backed parity/superiority verdict, detects uniform-small-edge the mean CI misses, and is the precondition for ever claiming 'indistinguishable from experts'. Pure-function, fully unit-testable, no new deps.

#### P0.3 — Confidence-gated judge override of the pool  *(effort: M)*

- **Method:** AIA Agentic-Supervisor decision rule: accept the supervisor's revised probability ONLY on self-reported HIGH directional confidence; otherwise fall back to the pooled aggregate. Bounds downside (a low-confidence judge can never drag the number off a sound pool) while capturing the documented lift.
- **Implementation:** Add directional_confidence: Literal['high','medium','low'] to JudgeSynthesis (quorum.py:127-152), require it in build_judge_prompt's JSON schema (quorum.py:318-331) and parse_judge_response (quorum.py:366-379). Add a PURE function resolve_final_probability(aggregation, judge)->(prob, source): returns (judge.probability,'judge_high') iff judge.probability is not None AND directional_confidence=='high', else (aggregation.aggregate_probability,'pool'). Wire into run_quorum (quorum.py:573-615) so QuorumResult carries final_probability+final_source; quorum_jobs.py:200-210 commits final_probability (not the raw pool). Store final_source on panel_runs (ledger.record_panel_run, ledger.py:4225-4288). Compose: the terminal Platt (P0 #1) applies to whichever number wins.
- **Files:** forecasting/quorum.py (JudgeSynthesis, build_judge_prompt, parse_judge_response, resolve_final_probability, run_quorum, QuorumResult), forecasting/quorum_jobs.py:200-210, forecasting/ledger.py:4225-4288
- **Expected gain:** Paper: Agentic Supervisor 0.1125 vs Simple Mean 0.1140; the override is the mechanism that lets the supervisor BEAT the mean instead of merely matching it, with bounded downside.

### P1 — the agentic-supervisor + honesty layer

Numeric prior stays the geomean pool; the judge adjudicates with evidence.
- **Implementation:** Two-phase judge in quorum.py: phase 1 prompt asks for clarifying_queries: string[] targeting contradictions; run through tools/web_tools.web_search_tool / news_search (the judge_runner is already an AIAgent with toolsets ('forecasting','web'), quorum.py:621 — simplest form: raise its max_iterations and instruct _JUDGE_SYSTEM to run base-rate/fact-check searches before answering). Append results as '## Resolution Evidence' to build_judge_prompt's user block; cap N=3 to bound cost. Persist queries+hits as supervisor_evidence on the panel run (ledger.record_panel_run). Combine with P0 #3: a search-resolved judge is the high-confidence path most likely to override.
- **Files:** forecasting/quorum.py:262-333,583-604, tools/web_tools.py, forecasting/news_search.py, forecasting/ledger.py (record_panel_run supervisor_evidence)

#### P2.3 — Help/hurt precondition gate + baseline-anchored extremization + hedging histogram diagnostic + alpha sweep  *(effort: M)*

- **Method:** Three guards that make the terminal Platt (P0 #1) SAFE and SHARP: (a) never extremize a wrong-sided regime (extremizing a wrong-side forecast amplifies Brier); (b) extremize the deviation from the reference-class BASE RATE, not from 0.5 (the web-context result that 'significantly outperformed all other methods' on 899 Metaculus questions); (c) confirm center-ward hedging actually exists before correcting (Fig.4); plus a held-out alpha sweep to justify sqrt(3) on OUR data.
- **Implementation:** 1) Baseline-anchored form in bayes_toolkit: platt_scale_anchored(p, base_rate, alpha)=inv_logit(logit(base_rate)+alpha*(logit(p)-logit(base_rate))) so the terminal stage extremizes AWAY from the reference class (which our status-quo/reference-class methodology already computes), not away from 0.5. 2) Help/hurt gate: before alpha>1 on a scope, check the scope's resolved hit-rate on its leaned side (reuse track_record edge, track_record.py:50); if <= 0.5+margin, force alpha=1.0. 3) diagnose_hedging(observations) in calibration_bias.py: histogram RAW pre-adjustment P(yes) (the Observation already documents the raw field at calibration_bias.py:159 — wire the ledger glue to populate it from learning.py:109 raw_probability), verdict 'center-ward-hedge' iff center-mass-fraction high AND SCE<0; only then recommend alpha>1. 4) sweep_platt_alpha(scores, alphas=linspace(1.0,2.5)) + leave-one-out variant in backtesting.py; surface the optimum + the sqrt(3) point in readiness (#138). 5) expected_brier_delta_by_bin(shape, alpha) from _curve_shape (calibration_bias.py:299) to confirm gains concentrate in the 0.2-0.4/0.6-0.8 bins (Fig.5) and never on saturated forecasts.
- **Files:** forecasting/bayes_toolkit.py (anchored form), forecasting/calibration_bias.py (diagnose_hedging, expected_brier_delta_by_bin), forecasting/ledger.py (populate raw p into Observation), forecasting/track_record.py:50 (help/hurt edge), forecasting/backtesting.py (alpha sweep + LOO), forecasting/dashboard.py

## Formal process-flow upgrades

- PIPELINE ORDER as a formal contract (the paper's recipe, made our commit path): research -> draw M~=10 independent forecasts -> pool in log-odds (geometric-mean-of-odds, our trimmed-geomean) -> agentic supervisor (disagreement detection -> targeted fresh search -> confidence-weighted synthesis; HIGH overrides, else fall back to pool) -> terminal fixed-alpha Platt on the single reconciled scalar -> (optional) simplex-constrained blend with de-vigged market price -> commit. Every stage records its pre/post probability so the chain is reversible and auditable. This replaces today's ad-hoc 'single update or sibling quorum' with one default multi-agent commit flow.
- Platt scaling == scaled-mean-of-log-odds extremization == Platt-of-the-geometric-mean-of-odds: formalize logit(p')=alpha*logit(p)+log(d) as THE one recalibration operator (platt_scale), prove the identity by aliasing extremize to it, and lock it with a regression test. This is the paper's headline 'previously-undocumented equivalence' and we already own both halves in two un-unified modules.
- Fixed-alpha convention from the closed form: d=n(sqrt(3n^2-3n+1)-2)/(n^2-n-1) (Neyman-Roughgarden) converging to sqrt(3) for n>50; adopt alpha=sqrt(3)~=1.73 as the theory-grounded default, but treat the magnitude as empirically falsifiable via a held-out alpha sweep + LOO on OUR resolved track record (the literature's 'theory gives the form, data gives the magnitude' refrain).
- Baseline-anchored extremization as a formal upgrade over extremize-from-0.5: log(O_hat)=log(O_baseline)+d*[mean_i log(O_i) - log(O_baseline)] — extremize the deviation from the reference-class base rate, which our status-quo/reference-class methodology already computes. The web context shows this 'significantly outperformed all other methods' on 899 Metaculus questions while the no-baseline form only matched simple averaging.
- Convexity/Jensen justification for averaging made explicit: Brier-of-the-mean <= mean-of-Briers, so the simple probability-space mean is the formal baseline any pool/judge must beat; geometric-mean-of-odds is externally-Bayesian and dominates the arithmetic mean. Record both on every run so the baseline is always visible and the variance is decomposed into sampling (LLM stochasticity) vs question variance.
- Confidence-gated override as a formal decision rule with bounded risk: final = judge.p iff directional_confidence==HIGH else pool — a documented, testable predicate (resolve_final_probability) rather than an implicit recording, giving asymmetric payoff (capture the supervisor's lift, never let a low-confidence judge regress below a sound pool).
- Foreknowledge as a two-CHANNEL taxonomy (pretraining-lookahead vs search-served-post-publication), each with its own mitigation: a model-cutoff gate for channel 1 and a high-recall content judge + dated-snapshot pinning + domain denylist for channel 2 — replacing today's single timestamp heuristic. Plus true-rate back-out (true_rate=(TP+FN)/N from precision/recall) so we NEVER report a raw flag count as the bias rate.
- Leakage robustness as a formal bound, not a flag: report the (baseline, filtered, worst-case) Brier triple; the superiority claim STANDS only if all three agree within ~0.001 (AIA Table 6). This converts leakage handling from a pass/fail kill-switch into a quantified upper bound on metric inflation.
- Paired recenter-at-zero bootstrap as the inference procedure: center per-question Brier deltas at zero, ~10k resamples, two-sided p-value + percentile CI + Win-Rate-vs-Best — the formal test behind any 'statistically indistinguishable from / better than experts' verdict, replacing the parametric normal approximation.
- Simplex-constrained Brier-minimizing regression as the formal market-blend: minimize mean (w.x - O)^2 over the simplex (w>=0, sum=1) with bootstrap CIs and a leave-one-out ensemble Brier; ship the blend ONLY where LOO beats both inputs, and weight by liquidity-driven data, not a fixed 50/50. Explicitly do NOT blanket-extremize the LLM+market blend (different methods).
